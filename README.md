# Ohmly

An interactive platform for learning electronics. Free, and it runs entirely in the browser.

Live at **https://ullnorse.github.io/ohmly/**

- 22 modules in four parts (foundations, building, going deeper, schematic to board), from Ohm's law to op amps, microcontrollers, motors, schematics, footprints, PCB layout and manufacturing
- 34 hands-on labs: animated circuits, an oscilloscope simulator, a filter you can hear, a 555 timer that blinks and plays tones, motors, logic, net tracing, schematic bug hunts, true-size packages, trace width, a decoupling loop, DRC hunts, Gerber layers and more
- Teardown: a real open-source board (ull-pocket, an ESP32-C6 environment meter) taken apart part by part, with every net traceable across its four copper layers, plus a timeline of its current from one day down to one I²C edge, four guided stories and a net probe
- 7 arcade games: Color Code Rush, Divider Designer, Gate Detective, Meter Madness, Formula Flashcards, Pop Quiz Roulette, Scope Sleuth
- 121 quiz questions with explanations, plus XP, levels and badges
- No build step, no dependencies, no tracking. Fonts are bundled.

## Run it locally

Open `index.html` in a browser, or serve the folder:

```sh
cd ohmly
python3 -m http.server 8000
# then open http://localhost:8000
```

## Publish it

It's a static site, so any static host works.

**GitHub Pages**
1. Create a new repository and push the contents of this folder to it.
2. In the repository, go to Settings → Pages, set Source to "Deploy from a branch", pick `main` and `/ (root)`.
3. The site appears at `https://<your-username>.github.io/<repo>/` after a minute.

**Netlify or Cloudflare Pages**
Drag the folder onto the Netlify dashboard (app.netlify.com/drop), or connect the repository in Cloudflare Pages with no build command and `/` as the output directory.

`og:image` in `index.html` points at `https://ullnorse.github.io/ohmly/og.png`. Update it, `og:url`, the canonical link and `<base>` in `404.html` if you move to a custom domain.

## Editing content

All course text lives in `js/data.js`. Each module has `n`, `part` (a key of `PARTS`: A, B, C or D), `title`, `blurb`, `big` (intro), `ideas`, `formulas`, `tip`, `labs` (lab ids from `labs.js`), `quiz` (`q`, options `o`, index of the right answer `a`, explanation `w`) and an optional `reading` note. `PARTS` maps each part key to `{name, desc}`; the contents page, sidebar and Practice filter list every part that has modules. Two optional fields add sections that are hidden when absent:

- `ex: [{q, steps:[...], ans}]` worked examples, one numbered step per line, units at every step.
- `deep: [{t, body}]` collapsed "Going deeper" entries, never counted toward completion. In `body`, blocks are separated by a blank line; a block of `= ` lines is a formula, a block of `- ` lines is a list, anything else is a paragraph.

Module pages have tabs, addressed as `#m-1/quiz`: Lesson, Notes (intro, key points, formulas, worked examples, going deeper, note, reading), Labs, Practice, Quiz. A tab with no content is hidden. Lesson is the default when the module has one, otherwise Notes. `#lab-<id>` opens Labs and scrolls to the lab.

## Lessons

`BC.LESSONS[moduleNumber]` in `js/lessons.js` is `{xp, widget, hotspot, steps, end}`. Each step has `id`, `kind`, `prompt` (at most about 15 words), `insight` (at most about 20 words, shown on success), `setup(s, vals)` and `ro` (readout cells), plus by kind:

- `do`: `actions`, `sliders`, `goal(s)`.
- `hit`: `sliders`, `target: {of, to, tol, show}`.
- `predict`: `choices: [{t, ok}]`, `reveal(s, choice)`, `settled(s, solved)`, optional `retry`. The first guess is recorded in `pred` and shown as "you predicted N of M" at the end, with no penalty.
- `probe`: `points: [{id, node, label}]`, `targets: [{t, test(dv, s)}]`.

`keep(s, vals)` stores numbers for the end screen, whose `end.rows` light up each formula of the module with a value the learner produced. No formula appears before that screen. Progress is in `S.lessons[n]` (`step`, `max`, `done`, `vals`, `pred`); XP is paid once through `BC.once("lesson-<n>")`.

A step's `sliders` are `{k, label, min, max, step}` or `{k, label, log: [lo, hi]}`, with optional `fmt(s)` for the printed value and `grip` to drag the part in the picture: `{node}` lifts a node, `{edge, sign}` drags a resistor's slope, `{walk: 1}` moves the walk marker. `goal(s, solved)` also gets the solution.

A widget is `{circuit(s), fresh(), tick(s, solved, dt), busy(s), ro, val, fail, clean?, alt(s, solved)}`. `tick` returns an event name when a part fails, `fail[event]` names the edge that bursts, `clean[event]` leaves out the smoke, and `alt` is the picture's text alternative. Read `vals` in `setup` to carry a learner's number between steps.

The picture is driven by a circuit description: `{gnd, vmax, iref, pref?, rspan?, nodes: {id: {at: [u, v], flat?, pad?, tag?, gauge?, was?}}, edges: [{id, t, a, b, ...}], walk?}`, solved by nodal analysis. Height is node voltage on one scale per circuit (`vmax`), so a circuit's heights compare directly; set `vmax` once per widget and leave it. Plan coordinates are free, so any series or parallel layout works. An edge marked `ghost` draws but does not conduct until the lesson opens it.

Stream width and speed each follow the square root of current over a fixed grain, so the charge a stream carries is proportional to current and adds up at a junction. Edge types are in `TYPES` (`wire`, `resistor`, `switch`, `fuse`, `source`, `capacitor`, `inductor`, `diode`). A new part needs one `TYPES` entry: `g(e,h)` for its conductance, `solid(c)` for its blocks and `symbol(c)` for the schematic. A switch with `Roff` leaks through that resistance when open.

Parts with memory are companion models. `capacitor` holds `v0`, draws as a glass tank whose footprint is `box` and whose water level is its voltage. `inductor` holds `i0` and draws as a flywheel. Add `j(e,h)` for an injected current and `commit(e,v,I)` to store state. `solve(d)` reads the circuit at this instant; `timeStep(d,run,hmax)` advances it by `run` seconds of model time with backward Euler. `diode` is an ideal `Vf` plus `Ron`, and `flip(e,v,I)` lets any part change state until the solution agrees with it.

`diode` takes `Vf`, `Ron`, optional `Vz` (breakdown), `dead` (burnt open) and `col`/`k` (LED light). `bjt` takes `base`, the edge whose flow sets it, with `hFE`, `Vsat`, `Rsat`, `Imax`. `mosfet` takes `ctl`, the node whose height sets it, with `Vth`, `k`, `Imax`. Both draw a gate blade and a dashed control line. `stray` is a weak source (`G`, `V`) standing in for a floating gate.

A description with `live: true` runs on its own clock: heights follow the model without the spring, and `vmax` may change, in which case the scale eases and the back walls relabel. `clock: {t, scale}` prints the time and how much it is slowed; `trace: {label, pts, tMax, yMax, guides, ticks, side}` plots a run. A widget with time adds `running(s)` and `quantum(s)`; under reduced motion the engine calls `tick` with one quantum every 650 ms.

Under reduced motion nothing loops: the picture settles at once, with static grains and arrowheads standing in for flow.

## Teardown

`#teardown` shows one real open-source board, [ull-pocket](https://github.com/ullnorse/ull-pocket) rev 0.8 (CERN-OHL-P-2.0), drawn from its KiCad files. Parts are addressed by reference (`#teardown/U7`), nets by name (`#teardown/net/%2B3V3`) and design notes by number (`#teardown/note/1`).

The board geometry is generated once and committed, so the site still has no build step. To regenerate it from a checkout of the board:

```sh
python3 -I tools/kicad2ohmly.py ../ull-pocket/ull-pocket.kicad_pcb data/ull-pocket.json
```

The converter only reads the board file. It writes the outline, footprints and pads, tracks, vias, simplified copper pours, keep-out areas, silkscreen and per-part MPN, LCSC and description, with coordinates in millimetres from the board's top-left corner. Its docstring lists the JSON schema. The page fetches the file, so serve the folder over http to use Teardown locally.

Part cards, net notes and design notes are in `js/teardown.js`: `BLOCK_OF` puts each reference in a block, `P` holds the card text (`t` title, `d` role, `k` key numbers, `m` module and lab links), `NN` holds net notes and `TD.NOTES` the numbered design notes. A part without a card gets a description built from its footprint data and nets. Use the board's own notes and the datasheets for numbers, and leave out any you can't source.

The timeline, stories and probe are in `js/teardown-time.js`. `F` holds each current with its source, `PH` the firmware phases built from it, and `buildScen` lays phases out as a day on battery, a USB plug-in or a reversed cell; the timeline, probe and story numbers all read from that one model. I²C frames are encoded bit by bit (`XFER`) and drawn with RC edges from the pull-up and an estimated bus capacitance (`EST`). Stories are in `STORIES` and open at `#teardown/story/<id>/<step>`. The firmware sequence is an example and the currents are datasheet typicals, so the page labels them as estimates.

## Practice problems

Add templates to `BC.PROBLEMS[moduleNumber]` in `js/problems.js` (3 or 4 per module). A template is a function returning `{q, ans, unit, steps}` with random values, plus optional `tol` (relative, default `0.02`) and `std:true` (also accept the nearest E12 or E24 value). For answers that are not SI quantities (millimetres, part counts, size codes), set `si:false`: `ans` is then a plain number in `unit`, typed without prefixes, and `show` overrides how it is displayed (`show:"0603"` for `ans:603`). `ans` is in base SI units (A, V, Ω, W, Hz, s); build `steps` from the same numbers as `q`, with `BC.fmt` for prefixes. The module's Practice section and the Practice page drill pick new templates up automatically; the drill draws only from modules that have templates. XP (15) is paid once per template, stored in `probs` as `"module-index"`.

Answers go through `BC.parseSI`: `4.7k`, `15m`, `2.2u`, `2.2µ`, `1M`, `1meg`, `4k7`, `1e-3`. A unit after the number (`mA`, `kΩ`, `Hz`) is ignored.

Reference sections are listed in `reference()` in `app.js`; add one entry per new section.

Progress is stored in `localStorage` under the key `ohmly-v1`. If you change the structure of the state, bump the key or add a migration.

## Before you publish

- **Licence.** `LICENSE` is MIT for the code and CC BY 4.0 for the course text (`js/data.js`). Change it there if you disagree.
- **Check the name.** Search for existing products called "Ohmly" before you buy a domain.
- **Book references.** Modules include a short "further reading" line pointing to printed page ranges of *Practical Electronics for Inventors* (4th ed.). It's a plain citation with no excerpts, and the site states it isn't affiliated. Remove the `reading` fields in `data.js` if you'd rather not reference any book.
